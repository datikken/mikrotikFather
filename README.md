# OpenVPN на VDS

Docker Compose-конфигурация OpenVPN-сервера для будущего соединения двух LAN через VDS. Серверный туннель работает в режиме TUN по UDP; LAN-маршруты добавляются отдельно для каждого клиентского сертификата. Сервер не включает NAT для трафика между клиентами.

## Подготовка VDS

На VDS установите Docker Engine с плагином Docker Compose v2 и Go 1.22 или новее. В панели хостинга разрешите входящий **UDP 1194**. Если на VDS используется firewall, разрешите этот порт там тоже. Не открывайте UDP 7777 на VDS: это порт обмена плат внутри VPN, а не порт VPN-сервера.

Передайте на VDS файлы проекта и из корневого каталога соберите CLI и создайте сервер:

```text
go build -o openvpnctl ./src
./openvpnctl create <публичный-IPv4-или-DNS>
./openvpnctl status
```

Например, укажите публичный адрес или DNS-имя VDS:

```text
./openvpnctl create vpn.example.com
```

Команда `create` генерирует конфигурацию, создаёт PKI (Easy-RSA запросит пароль CA) и запускает контейнер. Сохраните пароль отдельно: он потребуется для управления сертификатами. Команды `init` и `up` можно использовать по отдельности. Для остановки выполните `./openvpnctl down`; остановка удаляет контейнер и его Docker-сеть, но сохраняет PKI и настройки в `data/`.

## Добавление клиента позже

Создайте отдельный сертификат и укажите LAN, которая будет находиться за этим клиентом:

```text
./openvpnctl add-client radio 192.168.66.0/24
./openvpnctl add-client module 192.168.55.0/24
```

Команда создаёт профиль `clients/<имя>.ovpn`, запись `iroute` для клиента, маршрут в конфигурации сервера и перезапускает сервер, если он запущен. Для каждого клиента задавайте его собственную, непересекающуюся LAN-подсеть. Имя клиента должно быть уникальным. Профиль содержит закрытый ключ и создаётся с правами `0600`; передавайте его только по защищённому каналу.

Для подготовленной в задании пары MikroTik используйте одну команду:

```text
./openvpnctl add-mikrotik-pair
```

Она выпускает сертификаты и профили `clients/mikrotik-a.ovpn` и `clients/mikrotik-b.ovpn`, настраивает маршруты между ними и перезапускает сервер. `mikrotik-a` соответствует стороне Radio (`192.168.66.0/24`), `mikrotik-b` — стороне Module (`192.168.55.0/24`). Профили используют UDP, TUN, AES-256-CBC, SHA256 и `tls-auth`, совместимые с импортом OVPN-профиля в RouterOS. Для OVPN/UDP требуется RouterOS 7.17 или новее.

Команды управления:

```text
./openvpnctl status
./openvpnctl logs
./openvpnctl restart
./openvpnctl down
./openvpnctl up
```

## Планируемая схема

```text
192.168.66.0/24 (Radio) <-- OpenVPN TUN/UDP --> VDS <-- OpenVPN TUN/UDP --> 192.168.55.0/24 (Module)
```

OpenVPN использует UDP 1194, TUN-подсеть `10.8.0.0/24` и AES-256-CBC с HMAC-SHA256 для совместимости с RouterOS. Отключена отправка клиентам маршрута по умолчанию и DNS-настроек. Включена маршрутизация между VPN-клиентами. UDP 7777 не публикуется в интернет.

После копирования каждого профиля на MikroTik импортируйте его через меню **Interfaces → OVPN Client → Import OVPN Configuration** (либо соответствующую команду `/interface/ovpn-client/import-ovpn-configuration`). Укажите имя пользователя клиента и любой непустой пароль: сервер настроен на аутентификацию сертификатом и не использует парольную аутентификацию. Затем проверьте параметры созданного OVPN-интерфейса: `protocol=udp`, `mode=ip`, `cipher=aes256-cbc`, `auth=sha256`.

При подключении сервер отправляет каждому MikroTik маршрут к удалённой LAN. На обоих роутерах проверьте, что он появился в таблице маршрутизации, firewall разрешает `forward` для UDP 7777 между `192.168.66.0/24` и `192.168.55.0/24`, а masquerade не подменяет адреса этого трафика. Серверный маршрут и `iroute` на VDS сохраняют исходные IP-адреса; NAT для межсетевого трафика не включается. RTT менее 250 мс зависит от географии, маршрута и нагрузки VDS, поэтому его нужно измерить после подключения.

## Данные и резервное копирование

Каталог `data/` содержит конфигурацию OpenVPN, CA, закрытые ключи и клиентские сертификаты. Каталог `clients/` содержит готовые профили с закрытыми ключами. Оба каталога исключены из Git — храните их резервные копии в защищённом месте. Не публикуйте их и не отправляйте в систему контроля версий.

`./openvpnctl init` можно повторить: существующие конфигурация и PKI не перезаписываются. Для изменения публичного адреса отредактируйте `remote` в профилях клиентов после их создания и перезапустите соответствующий клиент.
